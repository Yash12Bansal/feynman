# 10 — Data Stores

**Branch:** `feat/unify_boardstate` · **Last verified:** 2026-05-28

## TL;DR

Feynman uses **four data stores**, each with a tightly scoped role:

| Store | Where | What | Owner | Authority |
|---|---|---|---|---|
| **Postgres** (`:5433`) | `docker-compose.yml` | Session lifecycle (`sessions` table) | `backend/` (FastAPI) | Cold/durable. |
| **Redis** (`:6379`) | `docker-compose.yml` | Session hot state (status, teaching_state, branch_depth) | `backend/` (FastAPI) + worker via FastAPI | Hot/ephemeral, 24h TTL. |
| **Neo4j** (`:7687`) | `docker-compose.yml` | Curriculum graph (Chapter, Topic, Diagram, Question) | `data_pre_compute_v2/` writes; `backend/` + `preview_server.py` read | Cold/durable. |
| **Filesystem** | `data_pre_compute_v2/artifacts/` | Audio MP3, diagram SVG/PNG | `data_pre_compute_v2/` writes; `preview_server.py` serves; frontend reads via HTTP | Cold/durable. |

Plus one auxiliary cache: `design_agent/generated/` holds every diagram spec ever generated by `design_bridge.generate_design_diagram`, for audit and re-use.

## 1. Postgres (`feynman` database)

Connection: `postgresql+asyncpg://feynman:feynman@localhost:5433/feynman` (configurable via `DATABASE_URL`).

Container config (`docker-compose.yml`):

```yaml
postgres:
  image: postgres:17
  environment:
    POSTGRES_USER:     feynman
    POSTGRES_PASSWORD: feynman
    POSTGRES_DB:       feynman
  ports: ["5433:5432"]
  volumes: [pgdata:/var/lib/postgresql/data]
```

Note the port: **5433** on the host (mapped to 5432 in the container). This is so it doesn't conflict with a local Postgres install.

### Schema

One table today: `sessions`. Created by Alembic migration `d36697d13f1b_create_sessions_table.py`:

```sql
CREATE TABLE sessions (
    id              UUID         PRIMARY KEY,
    room_name       VARCHAR(255) NOT NULL UNIQUE,
    subject         VARCHAR(50)  NULL,
    status          VARCHAR(20)  NOT NULL DEFAULT 'pending',
    teaching_state  VARCHAR(30)  NOT NULL DEFAULT 'idle',
    ended_at        TIMESTAMPTZ  NULL,
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX ix_sessions_room_name ON sessions (room_name);
```

Field map:

| Column | Source | Notes |
|---|---|---|
| `id` | `uuid4()` from `SessionManager.create_session` | Primary key. |
| `room_name` | `f"feynman-{uuid.hex[:12]}"` | LiveKit room name. Unique. |
| `subject` | `SessionCreate.subject` | `math`, `physics`, etc. May be NULL. |
| `status` | `SessionStatus` enum (`pending` → `active` → `ended`) | Written on `create_session`, `activate_session`, `end_session`. |
| `teaching_state` | `TeachingState` enum (`idle` → `greeting` → `teaching` → ...) | Hot path lives in Redis; Postgres is updated only on activate + end. |
| `ended_at` | `datetime.now(UTC)` from `end_session` | NULL while active. |
| `created_at`, `updated_at` | Server defaults + `onupdate=now()` | TimestampMixin. |

### How Postgres is touched

```
POST /api/sessions:
    SessionRepository.create(SessionModel)
    INSERT INTO sessions (...) VALUES (...)
    COMMIT
    REFRESH model

GET /api/sessions/{id}:
    # Tries Redis first; only hits Postgres if Redis miss
    SessionRepository.get_by_id(session_id)
    SELECT * FROM sessions WHERE id = $1

POST /api/sessions/{id}/end:
    # Reads from Redis to capture last teaching_state
    SessionRepository.get_by_id(session_id)
    model.status = ENDED; model.ended_at = now()
    COMMIT
    REFRESH model
```

The teaching state machine **does not write to Postgres on every transition** — that would be too chatty. State transitions in the worker write to Redis via `SessionManager.update_teaching_state(session_id, state, branch_depth)`. Postgres is touched only at activation and termination.

### Alembic migrations

Located in `backend/alembic/versions/`. Run with `make migrate` (alias for `uv run alembic upgrade head`). Auto-create on dev startup also happens via `Base.metadata.create_all` in `main.py:35-37` so a fresh dev environment "just works."

Current state: one migration, one table.

Knowledge graph migrations will land when `backend/src/feynman/knowledge/` is wired (today it's stubs). Design intent (per `knowledge/CLAUDE.md`): per-subject knowledge graphs with a shared student profile, modeled with the abstract-repository pattern over Postgres.

## 2. Redis (hot session state)

Connection: `redis://localhost:6379/0` (configurable via `REDIS_URL`).

Container config:

```yaml
redis:
  image: redis:7-alpine
  ports: ["6379:6379"]
  volumes: [redisdata:/data]
```

### Storage pattern — `SessionRedisStore`

One hash per active session. Key: `session:{session_id}`. TTL: **86400s (24h)** — sessions auto-expire if not explicitly ended.

```
HASH session:<uuid>:
    status          = "pending" | "active" | "ended"
    teaching_state  = "idle" | "greeting" | "teaching" | "asking_question" | ...
    branch_depth    = "1"  (stringified int; "1" = main branch, "2"+ = inside doubt)
    room_name       = "feynman-abc123..."
    subject         = "physics" (or empty)
    created_at      = "2026-05-28T12:34:56+00:00"
    updated_at      = "2026-05-28T12:35:01+00:00"
```

### How Redis is touched

```python
# Session create (manager.py:36-63)
HSET session:<id> mapping={...}
EXPIRE session:<id> 86400

# Session read (manager.py:65-77)
HGETALL session:<id>     # hot path; Postgres fallback only on miss

# Activate (manager.py:87-105)
HSET session:<id> status=active teaching_state=greeting updated_at=<iso>

# Teaching state transition (manager.py:107-119) — the hot path
HSET session:<id> teaching_state=<state> branch_depth=<depth> updated_at=<iso>

# Session end (manager.py:121-142)
DEL session:<id>          # after syncing final state to Postgres
```

`decode_responses=True` on the client (`redis/client.py:9`) — Redis returns strings, not bytes. ISO timestamps and enum string values are stored as-is.

### What does not go in Redis

- **Teaching context** (`TeachingContext` from `agent/teaching_context.py`) — lives in the worker process's memory only. When the worker disconnects or the room closes, the in-memory state goes with it. If the same session reconnects, the teaching context is rebuilt from scratch.
- **Board state** (`BoardManager`, `BoardState`, `SceneGraph`, etc.) — also in-memory only.
- **Concept plans** (`ConceptTeachingPlan` from kernel) — in-memory only.
- **Audit events** (`SessionAudit`) — in-memory only.
- **Doubt state** (`DoubtState`, `ReturnAnchor`) — in-memory only.

The choice is deliberate: serializing this state would be expensive, and reconnect-resume isn't a v0 product requirement. If a teaching session is interrupted, the student starts a new session.

## 3. Neo4j (curriculum graph)

Connection: `bolt://localhost:7687` (configurable via `NEO4J_URI`).

Container config:

```yaml
neo4j:
  image: neo4j:5
  ports: ["7474:7474", "7687:7687"]
  environment:
    NEO4J_AUTH:    neo4j/password
    NEO4J_PLUGINS: '["apoc"]'
  volumes: [neo4jdata:/data]
```

Browser UI at `http://localhost:7474` (login `neo4j` / `password`). Bolt protocol on `:7687`.

### Schema

Four node labels:

| Label | Key field | Other fields |
|---|---|---|
| `Chapter` | `chapter_id` (unique) | `chapter_index, title, summary, page_start, page_end, topic_ids, chapter_manifest (JSON), narration_text, board_snapshots (JSON), concept_visual_index (JSON), lecture_plan (JSON), lesson_plans (JSON), lesson_narrations (JSON), assembled_chapter_script (JSON), embedding, version, language, ...` |
| `Topic` | `topic_id` (unique) | `chapter_id, section_number, within_chapter_order, topic_name, our_understanding, orig_book_content, book_examples (JSON), next_topic_id, prereq_topic_ids, has_diagram_ids, has_question_ids, standalone_manifest (JSON), standalone_narration_text, embedding, needs_review, language, version` |
| `Diagram` | `diagram_id` (unique) | `renderer, render_data (JSON), description, fallback_image_url, linked_topic_ids, linked_beat_id, presentation_mode, needs_review, version` |
| `Question` | `question_id` (unique) | `q_text, q_audio_url, q_diagram_id, answer, answer_audio_url, options, type, source, solution_confidence, linked_topic_ids, needs_review, language, version` |

Five edge types:

| Edge | From | To | Purpose |
|---|---|---|---|
| `CONTAINS` | `Chapter` | `Topic` | Hierarchy. |
| `NEXT` | `Topic` | `Topic` | Lecture flow ordering. |
| `PREREQ` | `Topic` | `Topic` | "Source depends on target." Reference only, not used for navigation. |
| `HAS_DIAGRAM` | `Topic` | `Diagram` | Association. |
| `HAS_QUESTION` | `Topic` | `Question` | Association. |

### Constraints

```cypher
CREATE CONSTRAINT chapter_uid   IF NOT EXISTS FOR (n:Chapter)   REQUIRE n.chapter_id   IS UNIQUE
CREATE CONSTRAINT topic_uid     IF NOT EXISTS FOR (n:Topic)     REQUIRE n.topic_id     IS UNIQUE
CREATE CONSTRAINT diagram_uid   IF NOT EXISTS FOR (n:Diagram)   REQUIRE n.diagram_id   IS UNIQUE
CREATE CONSTRAINT question_uid  IF NOT EXISTS FOR (n:Question)  REQUIRE n.question_id  IS UNIQUE
```

Plus existence constraints (Enterprise only):

```cypher
CREATE CONSTRAINT chapter_title_exists  FOR (n:Chapter)  REQUIRE n.title      IS NOT NULL
CREATE CONSTRAINT topic_name_exists     FOR (n:Topic)    REQUIRE n.topic_name IS NOT NULL
```

### Indexes

Range indexes for sorted queries:
- `chapter_index` on `Chapter.chapter_index`
- `topic_section` on `Topic.section_number`
- `topic_chapter` on `Topic.chapter_id`
- `topic_order` on `Topic.within_chapter_order`
- `diagram_renderer` on `Diagram.renderer`
- `question_type` on `Question.type`

Composite range:
- `(Topic.chapter_id, Topic.within_chapter_order)` — used for "all topics in a chapter, in order" queries.

Fulltext indexes:
- `topic_search` over `(Topic.topic_name, Topic.our_understanding, Topic.orig_book_content)`
- `question_search` over `(Question.q_text, Question.answer)`

Vector index:
- `topic_embedding` (cosine similarity) at `EmbeddingConfig.dimensions` (default 384 for sentence-transformers `all-MiniLM-L6-v2`).

### JSON-valued properties

Several columns store JSON-serialized Pydantic models as strings:

| Property | Model |
|---|---|
| `Chapter.chapter_manifest` | `Manifest.model_dump_json()` |
| `Chapter.board_snapshots` | `list[BoardSnapshot]` serialized |
| `Chapter.concept_visual_index` | `ConceptVisualIndex` serialized |
| `Chapter.lecture_plan` | `ChapterLecturePlan` serialized |
| `Chapter.lesson_plans` | `list[LessonPlan]` serialized |
| `Chapter.lesson_narrations` | `list[TopicNarration]` serialized |
| `Chapter.assembled_chapter_script` | dict (segments) serialized |
| `Topic.book_examples` | `list[BookExample]` serialized |
| `Topic.standalone_manifest` | `Manifest` serialized |
| `Diagram.render_data` | renderer-specific spec dict |
| `Question.options` | `list[str]` serialized |
| `embedding` (on Topic/Chapter) | `list[float]` JSON-serialized |

This trades query-time deserialization cost for schema flexibility — JSON shapes evolve as the pipeline matures (e.g., adding `BoardSnapshot` on `feat/unify_boardstate`) without needing schema migrations.

### How Neo4j is touched

**Writer:** the precompute pipeline only.

```
data_pre_compute_v2/.../curriculum/ingestion/cypher_generator.py:
    yields CypherStatement(query="MERGE (n:Chapter {chapter_id: $cid}) SET n.title = $title, ...",
                            params={...}, category="node", uid=...)
data_pre_compute_v2/.../curriculum/ingestion/neo4j_writer.py:
    Neo4jWriter.ingest(statements, batch_size=50, initialize=True)
    Runs schema constraints if initialize
    Executes batches; one failed MERGE doesn't fail the batch
    Returns IngestionReport
    verify_ingestion() optionally checks expected nodes/rels exist
```

All statements are `MERGE`-based → ingest is **idempotent**. Re-running the pipeline on the same chapter overwrites in place.

**Readers (three):**

1. **`backend/src/feynman/agent/curriculum_loader.py`** — called by the LiveKit worker's `on_enter()` to load chapters + topics + diagrams + questions for the current teaching subject/topic. Uses the Neo4j Python driver async API.

2. **`data_pre_compute_v2/tools/preview_server.py`** (port 8080) — serves `/lecture-api/chapters` and `/lecture-api/chapter/{id}`. Returns the chapter manifest as JSON with URLs rewritten from `file://./artifacts/...` to `/lecture-artifacts/...`.

3. **`backend/src/feynman/agent/doubt_resolution/chapter_loader.py`** — used in lecture-playback doubt resolution to hydrate a `ChapterContext` (topics + diagrams + visual term lookup) when the student asks a doubt.

### CLI helpers

```
poetry run lecture-pipeline-v2 init-schema    # apply constraints + indexes
poetry run lecture-pipeline-v2 stats          # node/rel counts, review flags
poetry run lecture-pipeline-v2 query <cypher> # ad-hoc query with limit
```

## 4. LiveKit (signaling — not a data store, but in the same docker-compose)

```yaml
livekit:
  image: livekit/livekit-server:latest
  command: --dev --bind 0.0.0.0
  ports: ["7880:7880", "7881:7881", "7882:7882/udp"]
  environment:
    LIVEKIT_KEYS: "devkey: devsecret"
```

- `:7880` — HTTP / WebSocket (signaling)
- `:7881` — RTC TCP
- `:7882/udp` — RTC UDP

LiveKit doesn't persist anything across restarts; rooms are ephemeral. Auth in dev is `devkey/devsecret`; in prod you set `LIVEKIT_API_KEY/SECRET` env vars.

Strictly speaking this is signaling infrastructure, but it's part of the data plane in the sense that **all audio + visual instruction data flows through it**. See `04-livekit-agent-worker.md` and `07-contracts-and-protocols.md`.

## 5. Filesystem — precompute artifacts

```
data_pre_compute_v2/
├── artifacts/
│   ├── audio/
│   │   └── chapter_<chapter_id>/
│   │       └── <topic_id>_<role>_<index>.mp3
│   │           # role = "chapter" | "standalone", index = position in script
│   ├── diagrams/
│   │   ├── diagram_<diagram_id>.svg     # SVG rendering of render_data
│   │   └── diagram_<diagram_id>.png     # Phase 10 raster fallback
│   ├── animations/                       # Reserved (unused today)
│   ├── runs/                             # Per-run intermediate debugging
│   └── measurement_cache/
│       └── *.json                        # Notebook block height cache (Phase 3 layout)
├── out/
│   └── extraction.json                   # Full CurriculumExtractionResult dump (with --output)
```

### URL scheme

URLs are stored in Neo4j as `file://./artifacts/...`. The preview server rewrites them to `/lecture-artifacts/...` when serving manifests to the browser. The Vite dev proxy then maps `/lecture-artifacts/` → `http://127.0.0.1:8080`, so the browser downloads audio/PNGs from `preview_server.py`.

In production the same mechanism would translate to a CDN URL like `https://cdn.feynman/lecture-artifacts/...` via a config knob.

### File naming conventions

- **Audio**: `{chapter_id}/{topic_id}_{role}_{index}.mp3`
  - `role`: `chapter` for embedded-in-chapter playback, `standalone` for solo-topic.
  - `index`: sequential within the script segment.
- **Diagrams**: `diagram_{id}.svg` and `diagram_{id}.png`.
- The `chapter_id` and `topic_id` are deterministic (from textbook structure), so paths are stable across runs.

### Why filesystem (not S3)?

The pipeline runs offline on the developer's laptop. Putting MP3s + PNGs on local disk is the simplest possible thing. The URL-rewriting indirection means moving to S3 later is a config swap, not a code change.

### Audio cache

`AudioPipeline.synthesize_text(text, output_path)` keys by content hash. If the same narration text exists at the same hash, it reuses the file instead of re-TTSing. Narration changes auto-invalidate (different hash → different filename → re-render).

## 6. design_agent's `generated/` directory

```
design_agent/generated/
└── <YYYYMMDD_HHMMSS>_<prompt-slug>.json
```

Every diagram spec ever generated by `design_bridge.generate_design_diagram` (the production live path) gets persisted here. Used for:

- Audit — "what diagram did the agent draw for prompt X?"
- Replay — `design_agent/backend` exposes `/api/generated` to list these.
- Debugging — when a diagram looks wrong, open the JSON and see exactly what Claude emitted.

The persisted file is the *post-validation* DiagramSpec dict (not the raw Claude output). Identical specs (same cache key) are still persisted on every cache miss; the cache prevents the LLM call, but `design_bridge` does not de-duplicate file writes.

## 7. The in-memory teaching state

Not technically a store, but the answer to "where does the live teaching session's actual brain live?"

Per active room:

```
LiveKit worker process (single Python interpreter)
└── per-room JobContext (one per rtc_session())
    ├── FeynmanAgent (LiveKit Agent subclass)
    └── AgentSession.userdata: TeachingContext
        ├── state_machine: TeachingStateMachine
        │   └── _stack: list[BranchContext]  # 1 = main, 2+ = doubt
        ├── lesson_plan: LessonPlan
        ├── current_concept_index: int
        ├── concept_plans: dict[int, ConceptTeachingPlan]
        ├── curriculum: ChapterContext (loaded from Neo4j)
        ├── board_manager: BoardManager
        │   └── _boards: dict[board_id, Board]
        │       └── Board.state: BoardState
        │           ├── _elements: dict[element_id, BoardElement]
        │           ├── scene_graph: SceneGraph
        │           ├── board_graph: BoardGraph
        │           └── spatial_solver: SpatialSolver
        ├── audit: SessionAudit
        │   └── events: list[AuditEvent]
        ├── anticipation: AnticipationEngine
        ├── doubt_orchestrator: DoubtOrchestrator
        │   └── _active: dict[branch_id, DoubtState]
        ├── board_verifier: BoardVerifier
        ├── perception_feedback_queue: list[PerceptionFeedback]
        ├── last_diagram_claims, diagram_version, ...  (perception tracking)
        └── current_diagram_dictionary, active_highlights, active_annotations
```

This entire structure is **garbage-collected when the room closes**. No persistence. The Redis hot state (`teaching_state`, `branch_depth`) is the only crumb that survives a worker crash, and it's not enough to resume teaching — only enough to know that "session XYZ was mid-teaching when it died."

If you wanted resumable sessions, this is the structure that would need to serialize. It's intentionally not designed for that yet.

## 8. Schema migration discipline

| Store | Migrations |
|---|---|
| Postgres | Alembic. `make migrate` (= `alembic upgrade head`). Migrations in `backend/alembic/versions/`. |
| Redis | No migrations (ephemeral). Key prefix changes would need a one-time scrub. |
| Neo4j | No formal migrations. The pipeline's `init-schema` command (constraint creation) is idempotent. Adding new properties is free (Neo4j is schema-flexible). Removing properties or relabeling requires manual Cypher. |
| Filesystem | No migrations. Path conventions documented above; changing them requires a re-run of the pipeline. |

The precompute pipeline's `Chapter` and `Topic` Pydantic models have a `version: int = 1` field that's stored as a node property. This is forward-looking — when the schema changes meaningfully (e.g., the board_snapshots addition on `feat/unify_boardstate`), the version bumps and old nodes can be re-migrated on demand.

## 9. Data flow summary — who writes where

```
data_pre_compute_v2/  (offline, manual run)
  ├── Reads:  PDF file
  ├── Writes: Neo4j (Chapter, Topic, Diagram, Question + edges)
  └── Writes: artifacts/audio/*.mp3, artifacts/diagrams/*.{svg,png}

backend/ FastAPI  (per HTTP request)
  ├── Reads/Writes: Postgres sessions table (CRUD)
  ├── Reads/Writes: Redis session:* hashes (CRUD)
  ├── Reads:  Neo4j (rare — health checks)
  └── Writes: nothing else

backend/ LiveKit worker  (per active room)
  ├── Reads:  Neo4j (curriculum_loader, chapter_loader)
  ├── Reads:  Redis (sessions, on session activation)
  ├── Writes: Redis (teaching_state, branch_depth) on every state transition
  ├── Writes: design_agent/generated/*.json (every generated DiagramSpec)
  └── Holds:  in-memory TeachingContext (never persisted)

design_agent/  (standalone, dev only)
  ├── Writes: design_agent/generated/*.json (when used)
  └── Reads:  itself only

preview_server.py  (offline tool on :8080)
  ├── Reads:  Neo4j (Chapter manifests)
  ├── Reads:  artifacts/* (audio + images, served as static)
  └── Writes: nothing

frontend/  (browser)
  ├── Reads:  /api/sessions (Postgres + Redis through FastAPI)
  ├── Reads:  /lecture-api/chapters and /lecture-api/chapter/{id} (Neo4j through preview_server)
  ├── Reads:  /lecture-artifacts/* (filesystem through preview_server)
  └── Talks:  LiveKit data channels (visuals, bounds, board_capture, doubt_signal)
```

## 10. Operational notes

### Backup

- **Postgres**: `pg_dump` via Docker volume. Only the `sessions` table matters; it's small.
- **Redis**: Snapshot on demand. State is ephemeral so backups are usually unnecessary.
- **Neo4j**: `neo4j-admin database dump`. The curriculum graph is the **only durable LLM-derived content** — it's worth treating carefully.
- **Filesystem**: rsync `artifacts/` directory. Audio especially is expensive to regenerate.

### Reset commands

```bash
make db-down               # stops all containers, volumes preserved
make db-reset              # docker compose down -v && up -d   ← wipes everything
make migrate               # alembic upgrade head
```

For Neo4j specifically:

```bash
poetry run lecture-pipeline-v2 init-schema     # idempotent
poetry run lecture-pipeline-v2 query "MATCH (n) DETACH DELETE n"   # nuclear
```

For just the artifacts:

```bash
rm -rf data_pre_compute_v2/artifacts/*
```

## 11. What would change for production

In rough order of urgency:

| Concern | Today | Production |
|---|---|---|
| Postgres credentials | `feynman/feynman` in docker-compose | Managed secret. |
| Redis | No auth | Auth + TLS. |
| Neo4j auth | `neo4j/password` | Strong creds; consider AuraDB. |
| Artifact serving | `preview_server.py` on `:8080` | S3 + CloudFront. URL rewriting becomes a config knob. |
| Audio files | Local filesystem | S3. The hash-based cache key still works. |
| Diagram cache (`design_agent/generated/`) | Local | S3 with object lifecycle policy (90-day retention). |
| TLS | None in docker-compose | Terminated at the load balancer. |
| Backups | Manual | Automated daily (Postgres + Neo4j). Artifacts use S3 versioning. |
| Migrations | Alembic | Same, but gated through CI + a "do not auto-create tables in prod" flag. |
| Schema flexibility | Adding fields to Neo4j JSON columns is free | Same. But changing manifest event types requires a migration of `Chapter.chapter_manifest` JSON blobs. |

The architecture is **production-shaped** — it just needs hosting and credentials.
